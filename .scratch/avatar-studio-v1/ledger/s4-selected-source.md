# S4 - selected-avatar source archive

Specification: approved host `Context/V1/Avatar-Studio-V1-Implementation-Design.md` section 8.3 and A08. Root accepted this bounded archive-service proposal; root owns integration, builds, tests, editor operations and commits. Independent review is required, maximum three rounds.

## Round 1 - plan

Status: implementing a content-only archive service; not wired into publishing and not full S4/A08 completion.

Use explicit verified content paths, expected BLAKE3 hashes/sizes, package dependencies, stable plugin/mount/Blueprint and engine/SDK identities. Distinguish the selected content root (which may traverse the one verified avatar link) from the physical plugin root. No directory recursion or arbitrary source config/descriptor bytes enter the archive. Generate a minimal project, content-only plugin descriptor and formatVersion 1 sidecar from typed fields. Record code/third-party plugins as external prerequisites; distribution and compatibility are not inferred.

Require a caller-supplied monotonic snapshot validator and cancellation check. Hash the exact buffers written into the existing engine ZIP writer, enforce file/archive bounds, recheck inputs and validate the completed ZIP before same-directory atomic replacement. Monitor event loss/ABA and whole cook/source coherence remain G04 obligations of the caller. Preserve an existing archive on any failure. Engine ZIP writer ownership and void AddFile require explicit write/flush failure observation.

Planned real ZIP fixtures: sanitized entries and manifest hashes, exclusion of unlisted other avatar/config/cache files, invalid/traversing/case-duplicate paths, unsupported extensions, changed expected inputs, cancellation/invalidation and preservation of previous output. Link/reparse checks need a real owned filesystem fixture. Clean UE rebuild/install and live backend source freshness remain separate gates.

## Round 1 - implementation

Status: ready for independent source review and coordinator build/automation; not integrated into publish jobs. No tests, builds, editor operations or commits were executed by this implementer. Root compiled the preceding handle-promotion revision successfully; current exact-case checks, exclusive writer and four tests require the next real build.

Owned files are `Source/ConvaiPakManager/Public/Publish/CPM_AvatarSourceArchive.h`, `Private/Publish/CPM_AvatarSourceArchive.cpp` and `Private/Tests/CPM_AvatarSourceArchiveTest.cpp`. No publish types/jobs/subsystem or shared module descriptor changed. Existing V0 archive behavior remains on its existing path.

Decisions:

- The public API accepts a verified physical plugin root separately from a selected Content root. The latter may traverse exactly one junction at Content or its named plugin parent, and its resolved handle path must match physical Content. All actual reads use explicit paths under that physical root; directory reparses and multi-link files below it are refused. Path validation rejects traversal, drive/stream aliases, reserved Windows names, case duplicates and unsupported source extensions. Protocol identities and Blueprint/package casing use explicit case-sensitive comparisons because UE 5.8 FString operators ignore case.
- Only `.uasset`, `.umap`, `.uexp`, `.ubulk` and `.uptnl` files declared by the caller enter the ZIP. Every package needs one primary file. Dependencies must be inside the selected closure, Engine, declared native modules or declared external plugin mounts. This checks declarations; it does not discover actual registry closure or prove licensing/distributability.
- Parse the selected descriptor from bounded, verified bytes and require content-only NoCode with no native modules/build steps. Generate neutral content-only descriptor and `AvatarSource.uproject`, enabling only the selected avatar and explicit prerequisites. Do not copy original descriptor extras, host config, other avatars, cache/log/job files, links or third-party code. The generated wrapper adds no labels or AlwaysCook rules. External native/third-party prerequisites must be installed separately; no clean rebuild is claimed yet.
- `avatar-source-manifest.json` has `formatVersion:1`, `hashAlgorithm:blake3`, `plugin:{name,mount,blueprint}`, `engine:{version,build}`, `sdk:{fingerprint,profile}`, `requiredPlugins:[{name,version,fingerprint,modules,bundled:false}]`, `packages:[{name,dependencies,primaryFileBlake3}]` and `files:[{path,size,blake3}]`. Files list generated wrapper/descriptor and selected content; it excludes the manifest's self-hash. Success returns the exact manifest hash. The manifest format remains separate from backend version slot `ue-5.8-Raw`.
- Read at most the configured single-file cap (256 MiB default, 512 MiB hard maximum), with explicit 16 GiB total content/50,000-file limits and bounded metadata/dependency counts. Larger source packages receive a concrete unsupported-size refusal; no unbounded allocation fallback. Hash and write the same bytes through the existing engine ZIP writer. A small native IFileHandle uses CREATE_NEW to own the temporary file exclusively and observes every write/seek/flush failure, including the writer's closing central directory.
- Protect the output directory against replacement. After writing, retain a native archive handle denying writes/deletion, verify every ZIP entry using the real engine ZIP reader, recheck source hashes/descriptor/root resolution and caller monitor, then rename that same validated handle into the held output directory. No pathname reopen or unverified file can replace the validated bytes between verification and commit. [Windows FILE_RENAME_INFO](https://learn.microsoft.com/en-us/windows/win32/api/winbase/ns-winbase-file_rename_info) supports relative destination plus directory handle and replacement. Prior output is never deleted first; failure/cancellation removes only the owned temporary file. This is same-volume atomic publication, not a crash/power-loss durability proof.
- Before/after reads are insufficient for authored-input ABA or coherent cook/source timing. The caller must supply a monotonic snapshot validator that fails on event loss/unknown state; service success alone does not complete G04 or establish backend source freshness, a cooked artifact binding, upload success or same-ID update.

Coordinator verification: prescribed current real build, then `ConvaiPakManager.Publish.SelectedSource` and existing `ConvaiPakManager.Publish.SourcePolicy`/V0 regression filters. Four new cases are SanitizedContentAndManifest, RejectsUnsafeDeclarations, ChangeCancellationAndRecovery, VerifiedRootAndNestedLinkRefusal. They use real ZIP writer/reader and real owned NTFS junction/hard-link fixtures. Package file bytes are deliberately opaque owned archive fixtures; these are not valid UE assets or clean-project rebuild proof. Checks cover manifest bytes/hashes, explicit entry exclusion, case/traversal/extension/closure refusals, source changes before and after ZIP close, output tampering refusal, cancellation/monitor invalidation after temporary creation, byte-for-byte previous-archive preservation, recovery, both selected-root link shapes and nested/wrong-target/hard-link refusals. Fixture cleanup removes each verified owned junction before considering recursive cleanup.

Remaining material gates: actual automation results, independent review, disk-full/write fault injection, large MetaHuman package/memory behavior, clean-engine wrapper rebuild/install, caller preparation/monitor integration, publish policy wiring, live source upload/download freshness and full S4/A08 flow. No mocked backend capability is counted as complete.

## Round 1 - independent review

Reviewer: provision_s0. Verdict: **changes_requested**. Reviewed the complete source/header, four automation fixtures, S4/section 8.3/A08 requirements, installed UE 5.8 ZIP writer/reader and native project/plugin defaults. Reviewed CPM_AvatarSourceArchive.cpp SHA-256 2143B11EDCC0E7FF3F9BDB171570410BB9A649F1DDDB4E82B1D2DF49ECC4A352. No source edits, builds, tests, editor operations, archive creation or remote operations by this reviewer. Root owns the actual test results.

- **R1-continuous-archive-ownership (major):** CPM_AvatarSourceArchive.cpp:213,570-574 closes the sole CREATE_NEW handle when the ZIP writer is destroyed, then reopens Temporary by pathname. During that interval no handle pins the created object; a different file can replace it, and the cleanup at 533 also acts on the pathname. The later protected handle is useful but does not establish continuous ownership from creation, contrary to the implementation ledger's no-pathname-reopen claim. Expected entry count/hash checks are not a substitute for that ownership: the installed ZipArchiveReader.cpp:129-159 collapses duplicate names into a TMap and its public checks do not validate external link attributes. Retain the originally created native object continuously through writer completion, ZIP verification and handle rename, giving the writer a duplicate it may close. Add a real fixture that attempts replacement/writing at the writer-to-validation transition and proves denial, while cancellation/failure still preserves the prior archive and removes only the owned temporary object. Author acknowledged this finding and proposed the continuous original handle plus writer duplicate.
- **R1-wrapper-default-plugins (major):** CPM_AvatarSourceArchive.cpp:494-497 emits only FileVersion, EngineAssociation and Plugins in AvatarSource.uproject. Native FProjectDescriptor defaults bDisableEnginePluginsByDefault=false (ProjectDescriptor.cpp:21,129), and PluginManager.cpp:1728/2146 therefore allows unrelated engine plugins enabled by default. An explicit Plugins array alone does not establish the claimed selected-avatar/prerequisite-only wrapper. Set DisableEnginePluginsByDefault=true and verify it with the native project descriptor in the fixture; retain the explicit selected/prerequisite references. Actual clean-engine startup/build remains root's later gate.
- **R1-ZIP-name-encoding (minor):** IsSegment/IsIdentifier currently permit non-ASCII names, but the installed writer encodes entry names as UTF-8 and ZipArchiveReader.cpp:158 decodes with ANSI_TO_TCHAR. StringConv.h:1101-1106 explicitly documents loss for non-ASCII UTF-8 bytes on that conversion. A supported-looking Unicode content path reaches the full archive write and then fails entry lookup, despite passing preflight. Add an early explicit supported-name refusal with a Unicode filename fixture, or use a compatible verification path without modifying engine source. Preserve the previous archive and give a concrete compatibility reason; do not claim arbitrary UE filename support until it is demonstrated.
- **R1-native-engine-module-model (minor):** CPM_AvatarSourceArchive.cpp:346,409-413 allows only builtin CoreUObject/Engine script modules plus modules attached to plugin prerequisites. Valid references such as /Script/AIModule cannot be represented because AIModule is an engine module, not an installable plugin. The API should accept explicitly verified engine-native module declarations and record them in the versioned manifest, or clearly gate this unsupported source shape pending that model; never invent an Engine/AIModule plugin dependency. Add a fixture distinguishing declared engine modules, undeclared modules and external plugin prerequisites. This does not ask the archive service to discover or verify the preparation closure itself.

Decision replies:

- Explicit files, saved sizes and hashes are a sound narrow archive boundary. Paths reject traversal/drive/stream aliases, reserved names, duplicate casing and unsupported executable/config extensions. Actual reads check physical ancestry, native final paths, file kind and hard-link count. The selected-root link is verified against physical Content and never itself stored. No whole-child recursion or V0 job replacement was introduced.
- The generated manifest binds every selected primary package and every archived generated/content entry; a manifest self-hash is returned separately. Original descriptor extras are not copied, native code is excluded and declared plugins are marked bundled=false. Treat formatVersion=1 as a local source-format contract, separate from the existing backend Raw slot. The service cannot prove module ownership, licensing, Blueprint validity or source compatibility from typed declarations alone.
- Installed FZipArchiveWriter emits ZIP64 records, so the 16 GiB total bound is not incorrectly fed into a classic 4 GiB ZIP format. Its per-file buffering still duplicates a bounded content buffer and needs real large-package/memory evidence. The custom write handle observes write/seek/flush failures, including central-directory completion, and scope teardown closes the writer before cleanup. Disk-full/fault injection remains explicitly unverified.
- Cancellation and snapshot invalidation are polled while reading and before promotion; failures preserve previous output by inspection. The caller-provided monotonic monitor is an explicit prerequisite, not an implemented monitor or proof of coherent cook/source snapshots. The service is synchronous and creates no background lifecycle. Production integration must own the worker thread, per-host/per-avatar lease and monitor through publication; fixtures with always-valid callbacks do not establish G04.
- Existing tests exercise real native ZIP/NTFS mechanics with intentionally opaque small package bytes. They cover explicit exclusion, hash binding, changed bytes, cancellation after temporary creation, post-close source mutation, correct/wrong root links, nested reparses, hard links and previous-output preservation. They do not establish a clean UE rebuild/install, actual MetaHuman closure, policy/job integration or real source freshness. Keep those limits explicit.

Source and ledger are released to pakmanager_s0 for the four bounded responses. Re-review after root's actual build/tests; two review passes remain within the configured three-round limit.

## Round 2 - response

All four findings accepted. Current source/tests are released to root for serialized build and automation, then independent re-review. This implementer ran no build, test, editor or service operation. Full S4/A08 remains partial.

- **R1-continuous-archive-ownership:** the CREATE_NEW handle now requests read/write/delete and denies write/delete sharing from creation until terminal cleanup/promotion. The engine writer owns only a DuplicateHandle; closing its central directory cannot release the original file object. ZIP verification opens a read handle with AllowWrite/AllowDelete solely to coexist with our retained handle's access rights; the retained share mode still refuses all competing writers/deleters. Native metadata checks and final rename use the original handle. Failure marks that same object for deletion before closing it, with no pathname-based cleanup. A filesystem refusal to delete logs a concrete cleanup warning and leaves the owned artifact for recovery rather than deleting an unverified replacement path. The earlier implementation ledger's no-reopen claim was incorrect and is superseded by this continuously retained handle.
- Updated the real tampering fixture to recognize the writer's completed ZIP end record before attempting GENERIC_WRITE|DELETE on the temporary file. It requires ERROR_SHARING_VIOLATION during verification, mutates an owned source file after ZIP completion, and checks that the old good archive survives and the owned temporary object disappears. There is no artificial sleep or injected production test callback; the existing snapshot validator supplies the test observation point. The original and duplicate refer to one object across the writer-close boundary by native handle lifetime, rather than relying on a timing race being won in a test.
- **R1-wrapper-default-plugins:** generated project now sets DisableEnginePluginsByDefault=true. The fixture parses it with native FProjectDescriptor and asserts the actual bDisableEnginePluginsByDefault field plus the selected/prerequisite entries. A clean-engine startup/build is still a separate gate.
- **R1-ZIP-name-encoding:** generated identifier names are ASCII and content file paths containing non-ASCII characters receive an explicit reader-compatibility refusal before creating a temporary ZIP. The Unicode filename fixture asserts that reason, no temporary creation and preservation of the previous archive. Physical root directories may contain Unicode; only ZIP entry names use this bounded compatibility restriction. No engine change or unsupported arbitrary-filename promise.
- **R1-native-engine-module-model:** input now exposes RequiredEngineModules, defaulting to CoreUObject and Engine. Additional verified engine modules such as AIModule are representable without fictional plugin prerequisites; the manifest's engine object now includes modules. Module declarations are bounded/validated, duplicates rejected and dependencies remain fail-closed when undeclared. Tests distinguish explicit AIModule, absent AIModule, duplicate casing and the separately declared Convai plugin/module. This is caller-provided profile evidence, not automatic module ownership/distributability verification.

Public schema update shared with coordinator: engine is now `{version,build,modules}`; formatVersion remains the unpublished local version 1. Backend Raw slot naming is unchanged. Next required run remains the four ConvaiPakManager.Publish.SelectedSource cases plus SourcePolicy/V0 regressions; no fixture is counted as actual UE package rebuild or live upload/download evidence.

A variant requesting excessive directory access was refused with Windows 5; it was not retried. This distinguishes native host behavior from ZIP content, Unreal save/load or a missing delete permission on the source handle.

The current Microsoft FILE_RENAME_INFO page permits relative RootDirectory names, but its documented common null-root/full-path form is the empirically supported route on this host. Promotion now uses the normalized full extended destination path with null RootDirectory. The original CREATE_NEW file object remains held and supplies the rename handle; the output directory remains held without delete sharing throughout, and its resolved path is rechecked immediately before promotion. No fallback closes/reopens the source or deletes the previous archive. Failure returns the native error number and still disposes only the owned temporary object.

Coordinator also fixed a Windows header macro compile issue using `FILE_DISPOSITION_INFO DeleteInfo { true }`, preserving the same object-handle cleanup behavior. Current source is released for real Unreal archive fixture rerun and final bounded independent review. No builds/tests/native diagnostic were executed by this implementation agent.
