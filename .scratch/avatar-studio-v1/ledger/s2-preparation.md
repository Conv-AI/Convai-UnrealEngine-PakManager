## Round 1 - implementation

Status: partial; source extraction and tests prepared, no real Unreal build or automation run by this agent. This item is not all of S2. Persistent identities, uploader provisioning, incremental refresh and fresh child load/reference evidence belong to integration items.

Decisions:

- The shared SDK service uses plain options/report types; CPM's UENUM/USTRUCT names and public function signatures stay in PakManager. Converters bridge those types. Moving reflected types would require compatibility redirects and make this extraction unnecessarily risky. No PakManager, Studio, uploader HTTP or job dependency enters the shared module.
- Avatar and thumbnail implementations moved once; CPM retains forwarding functions. The CPM-specific `ECPM_AssetType` thumbnail shape adapter remains in CPM, so SDK preparation need not import publishing types.
- `bStrictValidation` is explicit and defaults false in both APIs. Existing V0 callers keep their behavior. Strict callers require saved Copy inputs, a settled registry, resolved dependencies and complete object mapping/save results. All slow-task dialogs now honor the existing `bSuppressUI` option.
- Existing V0 game-package overwrite intentionally skips an existing destination to avoid a World Partition crash while reporting it copied. Strict preparation rejects that case before mutation. Safely refreshing changed packages needs an Unreal-aware incremental mechanism and its own evidence; neither deleting/recreating the package nor silently retaining stale bytes is acceptable. This is an explicit partial capability, not implementation of the V1 delta algorithm.
- Strict preparation rejects partial Advanced Copy failure and unsupported multi-asset manual engine duplication. A failure may leave an incomplete newly prepared destination; it never creates a false successful baseline. Transactional rollback/journaling belongs to the orchestration caller and remains required before V1 publishing is complete.

Files owned: SDK worktree `Source/ConvaiAvatarPreparationEditor/**`; CPM `Private/CPM_DependencyCopyAPI.cpp`, `Public/CPM_DependencyCopyAPI.h`, `Private/Avatar/CPM_AvatarBlueprint.cpp`, `Private/Thumbnail/CPM_Thumbnail.cpp`; this ledger. Root owns `.uplugin` and CPM Build.cs integration.

Verification to run by root:

- Real prescribed host/SDK build with fresh `lastBuild.status == succeeded`; no Live Coding.
- Unreal automation `ConvaiAvatarPreparation.Copy`: saved-input refusal, refusal before replacing an existing destination, and already-contained saved package copying zero packages. Fixtures use unique owned mounts backed by `Saved/ConvaiAvatarStudio/PreparationTests`; no user avatar packages are modified.
- Existing `ConvaiPakManager.Avatar`, `ConvaiPakManager.Thumbnail` and then full `ConvaiPakManager` automation confirm facade behavior, reflected integration and V0 regressions.
- Required later integration evidence: fresh copy and cross-package hard/soft references, intentionally failed load/save, changed-dependency refresh, and actual fresh child compile/load with real MetaHuman content. The focused tests above do not prove those scenarios.

No tests or build run by the implementation agent; root serializes them after integration. No commit, push, PR, release bump or editor mutation performed by this agent.

## Round 1 - review

Reviewer: `sdk_s0`, independent of preparation implementation. Verdict: **changes_requested**. Reviewed the actual SDK extraction and CPM base `0218c2b` facades, approved preparation design and S0 ledger; no build, tests, editor operation or source mutation by reviewer. Root reports a successful real build and 80 passing automation cases (78 success, two existing warnings), including the three new preparation cases; those cases do not cover the findings below.

- **R1-dirty-referencer (major):** `ConvaiAvatarPreparationEditor/Private/ConvaiDependencyCopy.cpp:124-130` checks only on-disk existence for `AdditionalPackagesToFixup`. A saved but dirty loaded referencer outside `AllPackages` passes, then is loaded at 1017, modified and saved by the fixup pass at 1078/1154. That can commit unrelated unsaved edits while strict preparation claims saved inputs. Apply the loaded-package dirty preflight to additional referencers before any copying. Add a saved/dirty extra-referencer fixture proving refusal, preserved dirty state and no created destination.
- **R1-unknown-closure (major):** `ConvaiDependencyCopy.cpp:429` discards `IAssetRegistry::GetDependencies`' boolean. UE 5.8 `AssetRegistryState.cpp:2194-2213` returns false when the dependency node is absent; that is unknown closure, not an empty resolved closure. A saved root not indexed by the registry passes `DoesPackageExist`, may copy successfully and receive a strict success with omitted dependencies. For strict queries which request dependency categories, refuse an unsuccessful registry lookup (or synchronously obtain and verify authoritative data before mutation); preserve default V0 behavior. Add coverage for a saved but unindexed source and for a genuinely indexed dependency-free source.
- **R1-engine-dialogs (major):** `ConvaiDependencyCopy.cpp:651-656` passes `bSuppressUI` only as a notification severity. UE 5.8 `AssetTools.cpp:2545` and `2634` call `LoopProgress->MakeDialog()` inside both Advanced Copy branches; `SlowTask.cpp:234` allows those in a normal host editor. Guarding only the module's own progress calls therefore does not deliver the ledger's “All slow-task dialogs” claim. Honor suppression for the invoked engine operation using a scoped supported engine mechanism, including failure paths, or explicitly refuse any strict unattended path whose prompting cannot be suppressed. Prove the host-editor case; commandlet tests inherently suppress progress and cannot catch this.

Decision replies: agree with preserving reflected CPM types and public APIs through converters; inspected fields/enums retain their values and all options/report fields are forwarded. Avatar and thumbnail extraction differs from the base only in includes, namespaces/log category and the CPM-specific WrittenShape adapter retained by the facade. Agree that V0's existing-destination skip stays default while strict refuses unverified replacement, and that failing load/save cannot be reported as a strict baseline. Correct the saved-input and dialog claims through the fixes above; they are code-level gaps within the new strict path, not requests to invent backend or incremental capabilities.

Acceptance boundaries remain partial as already recorded: the three automation cases cover refusal/no-op paths, not a fresh successful copy, real hard/soft remapping, injected load/save failure, incremental replacement, recovery or fresh child load/compile. Those unresolved integration gates are separate from this review's actionable findings and must not be marked complete by fixture success.
Planner clarification for R1-dirty-referencer: strict additional referencers must also be inside the normalized destination mount/subtree being prepared; reject an original/outside-destination referencer before mutation so ProjectSource preparation cannot rewrite authoring inputs. Default V0 API behavior remains unchanged. Required verification for the extracted main path is a fresh two-package fixture containing both a hard and a soft reference, checked after copy and save/reload: references point to the destination objects and original packages stay unchanged. The existing no-op/refusal cases cannot prove the moved copy/fixup path.

Engine suppression detail: `FSlowTask::MakeDialog` at `Engine/Source/Runtime/Core/Private/Misc/SlowTask.cpp:234` checks `GIsSilent`, commandlet state and slow-task visibility; it does not check `GIsRunningUnattendedScript`. An unattended-script guard alone cannot suppress those progress dialogs. Choose the scoped mechanism using actual engine behavior and restore prior state on every exit.

## Round 2 - implementation

Status: partial; review fixes and additional real-package automation written, awaiting coordinator build/test execution and independent review. The earlier three-case result does not verify these changes.

- R1-dirty-referencer: strict preflight now rejects each additional referencer unless its package is saved, clean when loaded, and inside the normalized destination subtree. A trailing slash enforces the subtree boundary, excluding similarly named siblings. Checks precede copy planning and all package copying/fixup/saving. Existing strict source/dependency checks also verify disk presence. V0 defaults and additional-referencer behavior with strict validation disabled stay unchanged.
- R1-unknown-closure: when dependency categories are requested, strict collection requires both a successful `GetDependencies` lookup and on-disk package registry data. An absent dependency node is unresolved; a placeholder node without package data also cannot establish known closure. Default V0 collection still ignores unsuccessful queries. This follows UE 5.8 `AssetRegistryState.cpp:2194` and `AssetRegistry.cpp:8270`, including the latter's recreation of empty dependency nodes for remaining referencers after removing package data.
- R1-engine-dialogs: after the game-thread check, synchronous preparation holds scoped `TGuardValue<bool>` guards for `GIsSilent` and `GIsRunningUnattendedScript` when `bSuppressUI` is enabled. The first suppresses engine-owned slow-task dialogs (`SlowTask.cpp:234`); the second suppresses `FMessageDialog` prompts (`MessageDialog.cpp:157`). Prior values are preserved when already set and restored on all returns. This corrects Round 1's incomplete suppression claim without relying on commandlet mode. It does not claim to suppress every nonmodal notification or supply host-editor evidence before execution.
- New private reflected test fixture carries real hard and soft references. `SavedHardAndSoftReferences` saves two unique mounted packages, confirms the registry recognizes the dependency and the indexed leaf's empty content closure, invokes the actual shared copy/fixup path, unloads all fixture packages without resetting the editor transaction buffer, reloads them and checks both copied references and original references. Original file bytes must remain identical. It also observes engine progress-dialog starts and verifies both suppression globals are restored; report entries identify commandlet/unattended/silent context so a commandlet success cannot be presented as normal host-editor dialog verification.
- `RejectsInvalidAdditionalReferencers` covers dirty, missing and outside-subtree inputs, with no created destination, no changed referencer file and preserved dirty state. `RejectsUnknownDependencyClosure` removes only its owned fixture's registry package data through the real registry API, first verifies the file remains saved and lookup fails, and requires strict refusal before a destination exists. Registry background processing is paused with its native scoped helper only during that case. These are local Unreal package tests, not backend integration.

No build, automation, editor, commit or service mutation run by this implementation agent. Source whitespace checks are separate from those required runtime checks.
